# AGENTS.md

Roost: a self-hosted personal email client for custom domains (single user, multiple catch-all domains).

## Stack

How the pieces fit: [docs/architecture.md](docs/architecture.md). Update it when a flow changes.

- `worker/` — Cloudflare Email Worker (TypeScript, wrangler). Writes raw EML + envelope metadata to R2 (retried twice), then a best-effort nudge to the backend. The R2 write is the only step that must succeed; if it fails, the Worker alerts Telegram directly and throws. No forwarding copy. Keep this code minimal.
- `server/` — PocketBase (module `ganigeorgiev.com/pocketbase/pocketbase`; the old `github.com/pocketbase` path is frozen, never use it) as a Go framework, not JS hooks. SQLite holds only indexed data; raw EML is written once to `mail/` at its R2 key path. MIME parsing with enmime; R2 via minio-go.
- `web/` — SvelteKit 3 SPA (`ssr = false`, adapter-static with `index.html` fallback), Tailwind 4, shadcn-svelte (vega style, lucide icons). Served by PocketBase from `pb_public`.
- Outbound: Resend (called only from the server). Alerts: Telegram bot.
- Deploy: one Docker image (`Dockerfile` at the root) with all state in the `/data` volume (`pb_data/` + `mail/`); back that volume up with any tool, so Roost ships no backup code.
- Package manager: pnpm workspace (`worker`, `web`). Go module: `roost/server`.

## Commands

Use the `justfile`; `just` lists recipes. Run `just check` (typecheck → lint → test → fmt; it stops at the first failure, so files are only reformatted once everything passes) before every commit, before staging.

## Conventions

- Imports in `web/` use `#lib/...` subpath imports (SvelteKit 3 has no `$lib`). Import component folders by their barrel file: `#lib/components/ui/button/index.js`.
- `web/src/lib/components/ui/` is generated by shadcn-svelte: add with `just web-ui <name>`, don't hand-edit; it is excluded from oxlint and oxfmt.
- Lint with oxlint and format with oxfmt, including `.svelte` files (configs at the repo root). Style: tabs, single quotes, 100 columns; Markdown keeps each paragraph on one line (`proseWrap: never`).
- No migrations. `server/internal/store/schema.json` is the schema, applied in full on every start (undeclared fields and collections are deleted). Change it in the admin UI, then `just server-schema-export` and commit; `TestSchemaRoundTrip` fails if the file is not canonical. The users collection's sign-in settings are the exception: kept from the database on sync unless `ROOST_PASSWORD_AUTH` / `ROOST_OAUTH2_*` set them, and stripped from exports (`store/auth.go`). OAuth2 sign-ins never create users (`api/auth.go`).
- The spool contract (key format, envelope metadata, nudge signature) is duplicated in `worker/src/` and `server/internal/`; change both sides together. A shared test vector pins the signature.
- Full-text search is an FTS5 trigram table (`messages_fts`) plus triggers, outside the snapshot; `store.Sync` (not `ApplySchema` alone) applies both on start. Add new searchable columns there.
- Threading lives in `server/internal/threading`: header links first (parent, siblings, late-parent merge), subject only as a guarded fallback. Thread counts are derived; change them through `threading.Recompute`, never by hand.
- Raw EML files are immutable. Purge deletes the DB row first, then the file. Parser changes reach old mail with `just server-reparse`.
- Ingest must be idempotent (dedupe on R2 key and Message-ID); nudge and sweep share one `ingest` function.
- Clients read through PocketBase's record API (list/view rules allow the `users` auth collection; there is no signup) and write only through `/api/roost/*` routes in `server/internal/api`; collection create/update/delete rules stay null.
- Outbound lives in `server/internal/outbound`. Drafts are `messages` rows (`direction = outbound`, `send_status` draft/failed, no thread); sending builds a raw EML copy (stored like inbound mail, Bcc kept only in the DB), calls Resend with an idempotency key of record id + Message-ID, then threads the message with `threading.Assign`. Every attempt and webhook event goes to `send_log`; webhooks are verified Svix-style and deduped on `svix-id`. Only domains with `send_enabled` can send (mail adds domains with it off); `identities` hold a display name and signature per address, applied to new drafts as a `-- ` block that the composer swaps when From changes.
- Alerts live in `server/internal/notify` and are best effort: ingest's `OnStored` hook only enqueues (never blocks or fails ingest), a background loop batches bursts (≤3 individual alerts, else one summary) and retries once on 429 or network errors. Imports don't alert. Escape all mail text for Telegram HTML; never log the bot token (it is in the request URL).
- Pipeline health lives in `server/internal/monitor` (cron, every 30 min): sweep can't list R2, spooled keys older than 2 h not stored (it ingests keys the sweep missed), and no mail for `ROOST_ALERT_IDLE_DAYS`. Alerts fire once, repeat daily, then send an all-clear; state is in memory. Bounces and complaints alert from a `messages` update hook.
- Sweep and trim use the newest ingested key not in the future (imports may carry bogus dates). The daily job trims `ingested_keys` a week past the R2 lifecycle window but always keeps the newest key. Oversize mail (`ErrTooLarge`) fails permanently; `roost ingest KEY` retries any key by hand.
- Archive and trash are thread-level (`is_archived`, `trashed_at`); new mail revives a thread. Trash purges after 30 days (daily cron).
- SvelteKit 3: route matchers live in `src/params.ts` (self-contained, loaded by plain Node at build), the service worker in `src/service-worker/` with its own tsconfig. CSP is a hashed meta tag from the kit config plus server headers.
- All inbound mail is untrusted: render text only, never inject email HTML, no remote images, sanitize attachment filenames and serve them as downloads.
- Secrets (Resend key, Telegram token, R2 credentials, nudge secret) stay server-side or in Worker secrets; never in `web/` or committed files.
